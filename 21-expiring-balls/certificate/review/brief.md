# Review brief: a certificate that 11 bins are not enough (experiment 21, follow-up)

New in the working tree (not committed): the folder `21-expiring-balls/certificate/` and edits to `21-expiring-balls/README.md` (the row "g(11) = 3", the "What to distrust" bullet "N(4) >= 12 now has a certificate", one sentence in "How the adversary uses expiry", Files) and the top-level `README.md` row for experiment 21. The game is defined in `21-expiring-balls/chain/3-question.txt`. The claim: a list C of positions (the certificate; the 11-bin one is too large to be in the repository, small ones are in `certificate/cert/`) defines a set S of positions, and the checker `certificate/check.cpp` accepts C only if S is a safe set for the Rule, which proves the Adversary cannot force load L on n bins. Because S is far too large to enumerate, the checker examines three finite families, and `certificate/PROOF.md` argues that this is enough. That argument is two pages, has ONE author, and is one day old. Assume it is wrong until you have traced it.
