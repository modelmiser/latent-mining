# Task: an independently checkable certificate that 11 bins are not enough for load 4

Background. Folder ../ (READ-ONLY for you) contains a two-player game (definition: chain/3-question.txt; overview: README.md). g(n) is the largest load the Adversary can force on n bins. The claim g(11) = 3 (so N(4) >= 12) currently rests on two backward-search programs, solver-b/back2.cpp and verifier/vb.cpp, whose COUNTS agree (attractor of 974,272,116 non-final states from 3,183,950 minimal seeds, empty state outside) but which share one idea (store a "core" of minimal winning states and test age-suffixes) and whose stored cores differ in size (3,723,730 and 3,722,933). There is no certificate. Read reports/referee.md (the section "The two halves of N(4) = 12" and "Follow-ups", item 1) and both programs.

Goal. Produce a certificate for "the Rule can keep every load below 4 on 11 bins, against FIFO expiry" together with a checker that is INDEPENDENT of the two existing programs' logic, so that a wrong certificate is rejected. Work only in  and start every shell command with `cd . &&`. Never write under ~/Claude.

What "certificate" should mean (design it so that the checker's logic is simple and local):
- The natural object is the Rule's side: a set S of states (up to relabelling of bins, keeping the age order of balls and which bin received each ball) such that (1) the empty state is in S; (2) no state in S has a bin of load 4... more precisely every state in S has all loads <= 3; (3) S is closed under Expire (removing the oldest ball); (4) for every state in S and every legal offer {u, v} (u, v in different components of the offer graph, over ALL 11 bins including untouched ones) at least one of the two answers leads to a state in S. Such an S proves g(11) <= 3 by induction on the play. For 6 bins the folder has this as an explicit list (solver-a/rule_n6_L3.txt, 3,843 states) with a checker (verifier/wcheck.py); for 11 bins an explicit list of the complement of the attractor would be far too large (the full state space is about 10^11).
- So the certificate must be COMPRESSED, and the checker must verify the four properties against the compressed form without trusting how it was produced. The referee's suggestion: dump the final core C of the Adversary's attractor (about 3.7 million codes); define A = { states having an age-suffix (i.e. the state obtained by deleting some number of OLDEST balls... check the programs for the exact direction: the attractor is closed under ADDING an older ball) in C }, and S = complement of A among states with all loads <= 3. The checker then has to establish, with C fixed and treated as untrusted data: (a) the empty state is not in A; (b) every state with a load-4 bin reachable in one Rule answer is handled (a state in S never has both answers leading outside S: for every state q NOT in A and every legal offer, at least one answer gives a state that is not in A and has no load 4); (c) closure of S under Expire. The difficulty is that (b) quantifies over all states not in A, which are too many to enumerate. Find a sound way to check it by enumerating something small. One route: show that if some state q outside A has an offer whose two answers both land in A (or reach load 4), then already a "small" state does, where small means a state all of whose balls matter, i.e. is built from core elements; derive precisely which finite family of states must be examined (for example: for each pair of core elements c1, c2 that could be the suffix witnesses of the two answers, the minimal state q whose two answers have c1 and c2 as suffixes), prove that derivation, and enumerate that family. Whatever route you take, write the soundness argument out as a short proof (PROOF.md) that a reader can check: why "checker accepts" implies "S satisfies (1)-(4)".
- If you cannot find a sound compressed check that fits the compute limits, say so plainly and deliver the next best thing with an honest description of what it does and does not establish (for example a forward closure in the style of solver-b's `back v` mode, or a third independent recomputation with a different state representation that does NOT use the core-plus-suffix idea), rather than a checker that merely re-runs the same search.

Requirements on the checker: written from the game definition, sharing no code with back2.cpp or vb.cpp; it must re-derive legality of offers, loads, components and FIFO expiry itself; it must be seen to REJECT deliberately damaged certificates (remove a core element; add a wrong one; change n); and first be validated on small cases where the truth is known and an explicit list exists: n = 6 with L = 3 (Rule wins; compare with solver-a/rule_n6_L3.txt), n = 7 with L = 3 (Adversary wins, so no certificate may be accepted), n = 8, 9, 10 with L = 4 (Rule wins).

Compute rules (someone's live workstation): every compute run prefixed with `nice -n 15`, at most 2 CPU cores in total for you, memory capped with `ulimit -v 12000000` in the same shell command, wrapped in `timeout 3000`; never more than two of your own compute processes alive at once; do not use ps, pgrep, pkill or killall; kill only your own PIDs; do not delete files; no network. Use TMPDIR inside your folder. Large output files are fine inside your folder (say so in the report), but keep anything meant for publication under 300 kB or say how to regenerate it.

Report (under 700 words) to REPORT.md if the harness lets you write it, and in any case return the same text: what the certificate is, the soundness proof in brief (and where the full one is), what the checker enumerates and how long it takes, the results on the validation cases and on n = 11, the rejected damaged certificates, exactly what remains trusted, and anything you could not do.
