### Important Points Not Asked About

1. **`verifier/vb.cpp` crash on default invocation (Most severe)**: While the mathematical method of `vb.cpp` is sound, running the headline command `./vb 11 4` without passing an explicit 3rd argument aborts after ~2 minutes with `table full` (`exit(3)`). The default exponent `lg = 22` caps entries at ~2.93M, but `n=11, L=4` inserts 3,722,933 core entries.
2. **Path fragility in `solver-a/verify12.py`**: Running `verify12.py` from repository root fails immediately because it opens `adv_n7_L3.txt` without directory anchoring.
3. **Fixed-capacity state structs in `solver-b/back2.cpp`**: `struct St` allocates arrays of length 12 (`r[12], o[12]`). While safe for `n=11` (where `k <= 9` before extension), running `n >= 12` would trigger out-of-bounds writes in `p.r[i+1]`.
4. **Omission of large certificates**: Safe-set witnesses for `n=8, L=4` (64 MB and 48 MB) and `n=10, L=4` (any-removal) are omitted from the repository due to file-size constraints. Verifying those specific claims requires regeneration rather than immediate witness checking.
