# Claude seat 2: experiment 21, general bounds and N(5) <= 21

All algebra redone by hand. I also wrote my own checker in scratch space (not the repo's code). It keeps real bin labels 0..n-1 and an explicit oldest-first ball list. It maps each table move back to real bins, with unnamed names going to distinct free bins, and checks legality on the real offer graph. Run on the repo's tables it accepts k=2/4, 3/7, 4/12 and 5/21, reaching exactly 13, 101 and 3,676 positions. On 5/20 it fails because it runs out of free bins. This agrees with `out_check_k5_n21.txt` and `organiser_check.txt`.

## Verdicts

**Q1: CONFIRMED.** `check_adv.py:99`: Expire drops `s[:-1]`, and since lists are newest-first that is the oldest ball. `:97` rejects Expire on an empty position. Offer legality: equal or negative names `:104`, the bin budget `m + unnamed_used <= n` `:106-108` with `m <= n` `:94`, and different components `:111`. An unnamed name is an isolated vertex, so it is always legal to offer. Both Rule answers are expanded at `:115-123`, and a load of L ends the line at `:117`. A position that is missing from the table is rejected at `:90`. Every table line must be in canonical form (`:75`), and every successor is renamed (`:99`, `:121`), so table keys and lookups use the same naming. Naming by first appearance over the age-ordered list (receiver first) is a complete invariant under bin renaming. Untouched bins really are interchangeable, because the state is only the set of present balls (`3-question.txt:1`). Acyclicity is needed because play must end. Without it, an Expire/Offer loop would let the Rule avoid load L forever while every reached position is still "in the table". The grey/black DFS at `:127-147` detects back-edges correctly. Every way I found to break the format (stray spaces, non-canonical keys, a ball like (0,0)) is rejected rather than accepted. I found no way to get a non-winning table accepted.

**Q2: CONFIRMED with exceptions.** `out_check_k5_n21.txt` and `organiser_check.txt` show accept on 21 bins, reject on 20, reject with target 6, and the k=4 pair. `out_solve_small.txt` gives n=2 win at L=1, n=3 loss and n=4 win at L=2, n=5 and n=6 loss and n=7 win at L=3. The damage claims are overstated, though (findings 1 and 2).

**Q3: CONFIRMED.** Lemma T and Lemma C check out: each feeding offer is legal because f's component has absorbed only c_j..c_(i-1). After c_i receives, every later offer pairs two bins of equal load m, so the load climbs to k. The FIFO use is right: p, q and q' are counted before any new ball arrives (PROOFS.md:49, 57, 68), so by (W) the expired balls are exactly the old ones. In Round 3 the D_1 ball comes after q' is counted, so it survives. Loads after each round are k−1 = (k−2)+1, (k−3)+2 and 1+(k−2). Footprints are s1 = 2^(k−2)+1, s2 = 2^(k−3)+2 and k. Bins per stage: k=5 gives 20, 21, 20, 21, and k=6 gives 37, 41, 40, 38. So b_5 = 21 and b_6 = 41. For k≥6, 9·2^(k−4)+1 ≤ 10·2^(k−4)+1, and k−1 ≤ 2^(k−3) holds for k ≥ 5. The induction uses P(k−1) only as a black box in Round 0, which is complete. Remark (iii): 28, 60, 124 are correct.

**Q4: CONFIRMED.** (a) s·r ≤ n−1. (b) A ball that i receives after t0 needs the other end v to be rich with an earlier stamp (otherwise v is poor, or v has the later stamp and takes the ball). v's rich interval contains t0, so v ∈ S\{i}. Its other ends are distinct by (F), which still holds under any-removal because offers are still between components. (c) floor((n−1)/r) ≤ k−r when n ≤ r(k−r+1). Edge cases: r=1 gives a bound of n−1 ≤ k−1; r=k gives k−1. k=1 and k=2 give 2 and 3, which are true but weak. max r(k+1−r) = ⌊(k+1)²/4⌋, giving 13, 17, 21, 26 against 2k = 12, 14, 16, 18. At k=5 the two bounds tie (10). "Between about k²/4 and k²/2" follows from 1+k(k+1)/2.
