# Review brief: Lean specification audit, latent-mining experiment 14

Repository folder under review: `14-forest-orientation/lean/` (present in the working tree; it may not be committed yet). You cannot run Lean here; this is a READING audit of a formal specification. A separate rebuild from clean sources succeeded and `#print axioms` shows only propext, Classical.choice, Quot.sound (`lean/BUILD.log`, `lean/AXIOMS.txt`); take that as given and do not spend effort on it. What a compiler cannot tell us is whether the definitions say what the informal problem says. That is your job. Assume the author (one instance of an AI model) is competent and that the specification is subtly wrong until you have checked each definition.

The informal game: `14-forest-orientation/chain/3-question.txt` (the authoritative statement) and `14-forest-orientation/README.md` ("The game"). The informal theorem: T(n) ≥ n/3 − (7/3)·log2(n+1) + 5/6 for every n ≥ 1.

The formal statement: `lean/FO/Spec.lean` (89 lines, all definitions) and `lean/FO/Main.lean` (the theorem `T_lower_bound`). Notes by its author: `lean/SPEC.md`. Sanity checks: `lean/FO/SpecCheck.lean`.

Questions. Give a verdict for each: CONFIRMED / REFUTED / UNSUPPORTED, with file:line evidence.

- Q1. `conn`: is the recursion on the edge list a correct definition of "same connected component of the undirected graph" for every list of arcs (including lists that are not forests, repeated edges, self-loops)? Argue it yourself; do not rely on the comment that `conn_iff` proves it.
- Q2. `moves`: are these exactly the Adversary's legal moves? Is anything legal in the informal game missing, or anything illegal included (u = v, ordered versus unordered pairs)? Does the game as formalised always keep the position a forest?
- Q3. `reorient`, `replies`, `valid`, `outdeg`: are the replies exactly "any assignment of directions valid for G + uv", including changing edges anywhere and more than necessary, and either direction for the new edge? Could a reply change the underlying undirected graph, drop or duplicate an edge? Is out-degree counted correctly?
- Q4. `flips`, `cost`: is the payment exactly "the number of old edges whose direction changed", with the new edge free? Check the list alignment (new edge at the head; `D'.tail` against `D`) for every reply produced by `replies`.
- Q5. `value`, `T`, `maxL`, `minL`: is `value` the minimax value of the n − 1 round game with the Adversary maximising and the Algorithm minimising? Is the order of quantifiers right (Adversary moves first each round)? What do the conventions `maxL [] = 0` and `minL [] = 0` do, can either case occur in play, and could either make the theorem easier than the informal statement (i.e. make T larger than the true value)? Is `T n = value (n-1) []` right for n = 1 and n = 0? Is defining the value by backward induction on positions, with no history, equivalent to the informal game between two deterministic players who see the whole history?
- Q6. The theorem: does `n + 3 ≤ 3 * T n + 7 * Nat.log2 (n + 1)` for all n ≥ 1 imply the informal inequality? Check the arithmetic, the meaning of `Nat.log2` (floor of log base 2), and whether the formal statement could be vacuous or trivially true (evaluate it by hand at n = 1, 2, 8 and one large n, using T(n) ≤ n − log2(n+1) from the README to see that it has content).
- Q7. Loopholes: is there any way the statement could be true for a reason other than the intended one? Consider: `Fin 0`; arithmetic truncation in `n - 1`; a `T` that is larger than the real game value because of an encoding choice; the theorem being about a different `T` than the one in Spec.lean (does any other file under `lean/FO/` redefine or shadow `T`, `value`, `moves`, `replies`, `cost`, or change them by attribute, notation, instance, `open` or macro? grep the files); universe or decidability tricks. Is `MainStatement` being a `def : Prop` proved by `FO.main` equivalent to the theorem?
- Q8. `lean/SPEC.md` and the README section "Machine check": does every sentence match the files? Are the ten listed encoding choices complete, or is there a choice not listed? Are the sanity checks in `SpecCheck.lean` meaningful (could each fail)?

For each defect give severity (CRITICAL: the formal theorem does not imply the informal one, or is vacuous; MODERATE: a real mismatch or unlisted encoding choice that does not break the implication; LOW: wording), file:line, and the replacement wording or definition you would use.
