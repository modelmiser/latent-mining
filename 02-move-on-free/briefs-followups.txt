You are a hostile but fair referee. Two solvers worked independently on the problem below. Their computed tables agree, but they DISAGREE about whether one lower bound is proved. THE GAME

Cells are 0, 1, 2, .... Fix M >= 3. Blocks have size 1, 2 or 3 and occupy contiguous cells. The heap starts empty. An adversary who sees the layout issues requests forever:
 - allocate(s), s in {1,2,3}: legal only if (live cells) + s <= M. The manager must immediately place the block on s contiguous free cells.
 - free(b): a live block chosen by the adversary vanishes.
Three games: N (no moves): blocks never move. F (move on free): right after free(b) with |b| = s the manager may perform moves whose moved sizes total at most s-1 (a move lifts one live block and puts it on any contiguous cells free once it is lifted; unused allowance is lost; so a freed 1 grants nothing, a freed 2 one move of a 1, a freed 3 one move of a 2 or up to two moves of 1s; 3s never move). O (only 1s freed): game N, but the adversary may free only blocks of size 1.
h^G(M) = least H such that some manager serves every legal infinite request sequence within cells 0..H-1. So h^O <= h^F <= h^N. mu^G = limsup h^G(M)/M.

THE SETTING

Online storage allocation on a line of cells, worst case, as a game. Blocks have size 1, 2 or 3. An adversary issues allocate(s) and free(block) requests, never exceeding M live cells; the manager must place each block on contiguous free cells at once. h(M) = the smallest heap (highest cell used + 1) some manager can guarantee. Three variants:
 - N: blocks never move (classical non-moving dynamic storage allocation with block sizes {1,2,3}).
 - O: as N, but the adversary may free only blocks of size 1 (larger blocks are permanent).
 - F: "move on free": freeing a block of size s lets the manager, at that moment only, move blocks of total size at most s-1 (so freeing a 1 grants nothing, a 2 lets it move one 1, a 3 lets it move one 2 or two 1s; 3s never move). The right cannot be saved up.

CLAIMS
 1. Exact values for M = 3..13: h^O = h^F = 4, 6, 7, 9, 11, 13, 14, 16, 18, 20, 21, and h^N the same except h^N(13) = 22.
 2. h^O(M) = 5M/3 + O(1): lower bound by keeping 1s on one residue class mod 3 then allocating 3s; upper bound by first fit.
 3. h^N(M) >= 7M/4 - O(1) for sizes {1,2,3} (claimed; under referee), and h^N(M) <= 43M/18 + O(1).
 4. Open: the asymptotic ratio for F; conjecture that it equals 5/3, i.e. that this tiny, non-bankable right to move makes the adversary's frees of large blocks useless.

What is the known constant for sizes {1,2,3}? Is 7/4 or 43/18 or some other value known? Also Luby, Naor, Orda "Tight bounds for dynamic storage allocation" (1996) and Knuth TAOCP vol. 1 section 2.5 exercises.
 2. Partial / bounded compaction: Bendersky and Petrank "Space overhead bounds for dynamic memory management with partial compaction" (POPL 2011 / TOPLAS), Cohen and Petrank "Limitations of partial compaction: towards practical bounds" (PLDI 2013), and later work; storage reallocation and "memory reallocation" (Bender, Farach-Colton, Fekete, Fineman, Gilbert, "Cost-oblivious storage reallocation"; Kuszmaul "Strongly history-independent storage allocation"; Naor and Teague); online interval/segment packing with migration or recourse ("dynamic bin packing with bounded migration", "online strip packing with recourse", Sanders-Sitters-Skutella style migration factor). Look for any model where the right to move is granted per deletion, proportional to (or less than) the deleted size, and not bankable.
 3. Any worst-case game analysis where only the smallest blocks may be freed, or a result that restricting which blocks the adversary may free changes the constant.
